# uniconnect

Sponsorship matching prototype that connects student groups (학생단체) with brands (브랜드). It is a pnpm workspace with a React frontend and an Express API. The UI copy is Korean.

## Commands

Run these from the repo root:

- `corepack pnpm@10.34.3 install` installs every workspace package.
- `npm run dev` starts the API on http://localhost:4000 and Vite on http://localhost:8443. Vite proxies `/api` to the API.
- `npm run typecheck` runs tsc for the backend and the frontend.
- `npm test` runs the backend API tests (`node:test` through tsx), then the frontend unit tests (vitest, `frontend/src/**/*.test.ts`, configured in `frontend/vitest.config.ts` without the app's Vite plugins). `frontend/src/lib/appPaths.sync.test.ts` checks `backend/src/lib/appPaths.ts` against `route.ts`.
- `npm run e2e` (after `npm run build`) runs the Playwright browser tests in `e2e/` against the built app on port 4300 with a fresh temp data file, in the installed Chrome (`channel: "chrome"`, no browser download): the main flows and axe accessibility checks (WCAG 2.1 A/AA; critical and serious problems fail).
- GitHub Actions (`.github/workflows/ci.yml`) runs install, typecheck, test, build and e2e on every push to main and every pull request.
- `npm run build`, then `npm start`, builds both packages and serves the API plus the built frontend from Express.

## Project Structure

- `frontend/src/App.tsx` holds the app state and the API calls, and switches between pages and modals for the current role.
- `frontend/src/api/` has the fetch wrapper with the Bearer token (`client.ts`) and one function per endpoint (`index.ts`).
- `frontend/src/pages/`, `modals/`, `layout/` and `components/` contain the UI. `data/`, `lib/` and `hooks/` contain constants and helpers.
- `frontend/src/layout/Header.tsx` is the fixed header: the logo on its own, then floating pills for the role's menu on wide screens, the next event, account buttons and Menu (registering is on the 내 행사 and 행사 일정 calendars and in Menu). The logo switches to its light version (`assets/brand/uniconnect_horizontal_reversed.svg`) over deep blue surfaces. `NavMenu.tsx` is the full-screen silver menu behind Menu and `Footer.tsx` the footer: the site's links, headed on the dashboard by a deep blue mesh card with linked chrome rings and the call to register (the whole footer is left out of a conversation).
- `frontend/src/scenes/` holds the WebGL effects: getlayers.ai's Antipode gradient (dashboard hero, detail banners) and Interference gradient (reports, measurement, analytics), run by `LayersGradient.tsx` from `shaders.ts`; Stride's mesh gradient, drawn once into an image (`MeshBackdrop.tsx`); and its chrome chain and rings (`ChromeScene.tsx`, `chromeModels.ts`).
- `frontend/src/index.css` is the single global stylesheet. Components use its class names, so a renamed class must change in both places.
- `backend/src/routes/` has one Express router per resource.
- `backend/src/data/seed.ts` holds the demo accounts and data.
- `backend/src/store.ts` is the JSON file store. It writes `backend/data/db.json`, which is gitignored; delete the file to reseed.

## Conventions

- `frontend/src/types.ts` mirrors the API shapes in `backend/src/types.ts`.
- Account types and sponsor types are listed in both `backend/src/lib/validation.ts` and the frontend (`data/roles.ts`, `pages/EventCreatePage.tsx`). Change them together. The same goes for profile fact labels and SNS platforms (`validation.ts` and `data/profile.ts`).
- Proposals go both ways through `POST /api/proposals`: a student group's reaches a brand with an account as a `SponsorRequest` (`/api/requests`, the brand's 받은 제안), a brand's reaches a group with an account as a `SponsorOffer` (`/api/offers`, the group's 받은 협찬, `pages/OffersPage.tsx`). Both inboxes share `components/RequestProgress.tsx` and the `request-*` classes, and `/api/proposals` answers each side's statuses.
- A listing's `logo` is a PNG, JPEG or WebP data URL of about 100KB at most, resized in the browser (`lib/image.ts`) and checked in `routes/profile.ts` (left out keeps it, null removes it); it lives in db.json for now.
- The brand and group catalogs are editable listings: each account's own listing is linked by `brandId`/`groupId` and edited from 내 정보. Recommended matches are the other catalog's top three, worked out in `backend/src/lib/catalog.ts`. Each listing's `score` (55–98) and `reasons` are worked out for the account browsing, or the demo account of that side for visitors, in `backend/src/lib/matchScore.ts`: industry fit 35, shared tag words 15, track record 20 (a brand's sponsorships, a group's event size), sponsored together before 15, ready to answer 15. The `score` stored on a listing is not used.
- Student groups and brands have separate menus and pages (`data/navigation.ts`). A feature for one side gets its own page rather than a role branch inside the other side's page.
- Every screen is a `View` with its own address (`lib/route.ts`), title and description (`lib/pageMeta.ts`). An address no screen has becomes a `missing` view, the 404 page; `backend/src/lib/appPaths.ts` lists the same addresses so the server answers the rest with a real 404, so change the two together. Change screens through App's `go` and `goBack`, never by setting state directly, so the browser's back and forward buttons and swipe gestures keep working. `lib/swipe.ts` adds swiping anywhere on the page through those entries (one finger, or two on a trackpad: left to right goes back, right to left forward), leaving swipes from the screen edge to the browser; `go` tells it through `noteHistoryEnd` how far forward history reaches, and the screen a swipe brings slides in from that side (`data-swiped` in the "Motion" section).
- Popups go inside `<Presence>` (`components/Presence.tsx`) so they animate closed however they are closed.
- The scenes load three.js lazily (the chrome chain and rings only once they come near view, `whenNearView` in `lib/lite.ts`), are left out for visitors who save data or are on a slow connection (`liteScenes`), pause off screen, hold still with reduced motion and leave a CSS background when WebGL is missing. Each live scene is its own WebGL context, so keep them few: a dashboard has three (hero, chain, footer rings) and other pages at most one besides the footer; the mesh draws through one shared context into images. A canvas keeps one context for life and React mounts effects twice in development, so a scene that loses its context on cleanup creates its canvas inside the effect (as `LayersGradient.tsx` does) or creates the context only after an async import. The getlayers.ai shaders are verbatim; retint them through their `config` only. The ShaderGradient (`components/GradientBackdrop.tsx`, lazily loaded `GradientScene.tsx`) heads only the login and sign-up popups (`<Modal banner>`). `three` is pinned to 0.182.0 because from r183 three warns that `THREE.Clock` is deprecated, and @react-three/fiber 9.8.1 still creates one for every canvas.
- The backend is ESM with NodeNext resolution, so relative imports end in `.js`.
- Express 5 forwards thrown and rejected errors to the error handler. Throw `HttpError(status, message)` with a Korean message the user can read.
- The UI is a light theme after getlayers.ai's Stride in deep blue and silver, with slate grays instead of black. Design tokens are CSS variables on `:root` in `index.css`: `--point` is the deep blue point color and text on it uses `--on-point` (`--point-strong` for blue text on white); `--point-bright` (on white) and `--point-glow` (on deep blue) are the accent blues for the words a block turns on, such as a heading's accent line; copy uses `--ink`, `--ink-soft` and `--muted`; silver fills use `--fill`/`--fill-strong` or `--silver-gradient` with `--silver-ring`; hairlines are `--line` or the inset `--ring`; dark tiles use `--slate`; goals met and not yet met use `--goal-met` (deep blue) and `--goal-short` (silver), and the goal line over them `--goal-mark` (amber). Use the tokens rather than new hex values. A deep blue surface also sets `--surface-tone: dark`, which tells the header to show the light logo over it. Copy over a moving gradient sits on a navy shade or frosted navy glass; check its contrast against the live canvas when moving it. The PDF report pages keep their own print colors on `.pdf-export`.
- Pages open with `components/PageIntro.tsx` (eyebrow, title, actions). Main actions use `components/Pill.tsx` (`primary`, `white` on blue panels, `silver`, `outline`, `outline-light`); `.primary-button` (deep blue), `.cancel-button` (outlined) and `.detail-button` (silver) are the same pill shapes and turn white on blue banners. Brands and groups show as `components/WorkCard.tsx`. The dashboards are built from `MeetingHero`, `LogoMarquee`, `RevealStatement`, `StatsBento` and `JourneyChain`.
- Text is Pretendard Variable from the `pretendard` package, imported in `main.tsx`, in the weights of the `--weight-*` tokens only: Bold 700 (display headings, large numbers and emphasis), Medium 500 (copy), SemiBold 600 (labels, buttons, card titles, the menu's pages), ExtraBold 800 (badges, counts), Black 900 (the wordmark) and ExtraLight 200 only for decorative large text (the chain's aside). Don't use 100, 300 or 400. The PDF exports (the students' report, `ReportDocument`, and the brands' analytics, `AnalyticsDocument`) render A4 pages off screen and write in only the font files the pages loaded (`report/pdf.ts`). Animated headings use `RevealTitle`, `RevealWords` or `RevealStatement` (`components/RevealText.tsx`) with plain text, and `RevealTitle`'s `accent` colors one line in the accent blue; they wait for the intro loader (`lib/intro.ts`), and headings with a digit stay still.
- Motion lives in the "Motion" section of `index.css`: a `stagger` class on a list makes its items arrive one after another, `data-reveal` makes a block rise out of a blur when it scrolls into view (`lib/reveal.ts`, delay with `--reveal-delay`), `components/AnimatedNumber.tsx` counts numbers up on arrival, and `lib/ripple.ts` adds the press ripple. Keep the reduced-motion rule at the end of that section. Tailwind v4 is available, but the UI is styled through the classes in `index.css`.
- Analytics go through `lib/analytics.ts` (`contact_click` on a press of 제안하기 or 문의하기, `generate_lead` once the server accepts a proposal, `sign_up`); they do nothing until a GA4 ID is set in `.figma/make/site.json`. Never put names, emails or message text in an event.
- Questions for the operators come from the FAQ page (`/api/inquiries`). Operators read and answer them on `/admin` (`pages/AdminPage.tsx`, in no menu), which calls `/api/admin` with the `ADMIN_TOKEN` environment value in the `X-Admin-Token` header (kept in sessionStorage for that tab only); those routes stay closed while it is unset. Question kinds are listed in both `backend/src/lib/validation.ts` and `frontend/src/data/inquiries.ts`.
- The terms of service and privacy policy (`/terms`, `/privacy`, `pages/LegalPage.tsx`) take their text from `frontend/src/data/legal.ts`. The privacy policy lists what the backend stores and how long; change it whenever stored data or retention changes. Both are drafts until an operator, contacts and a privacy officer are named.
- A forgotten password is reset through `/api/auth/password-reset/code` and `/api/auth/password-reset` (`modals/ResetPasswordModal.tsx`, opened from the login form). Reset codes are email codes with `purpose: "reset"` and share the sign-up codes' limits and carried-over guesses; a reset ends the account's other sessions.
- Leaving is `DELETE /api/auth/account` with the password (`modals/LeaveModal.tsx` from 내 정보). `removeAccount` in `backend/src/routes/auth.ts` deletes everything the account made; when a new collection holds an account's data, add it there and to the privacy policy. The demo accounts cannot leave. A wrong password answers 400, not 401, which the app treats as an expired session.
- Verification codes go out through Resend from `backend/src/lib/mailer.ts` once `RESEND_API_KEY` and `MAIL_FROM` are set, and only to the server log before; a failed send answers 502. Sign-up codes (never reset codes) also come back as `devCode` only while `EXPOSE_EMAIL_CODES=true`, which `npm run dev` sets through `backend/dev.env` and nothing else does. The privacy policy names Resend as the mail processor. `notify` (`lib/notices.ts`) emails the other side about a new proposal or offer, an answer, or a message (once per run of unread messages), with a link when `SITE_URL` is set; it never fails the request. Tests swap `mailTransport.post` to see what would go out.
- Measurement is per event: `Database.measurements` holds one `Measurement` per event (counts, scans by hour, latest records, check-in `code` and goals), created with default goals when an event is first opened (`backend/src/lib/measurements.ts`). Reports are worked out from it in `buildReport` (reach = scans + `snsReach`, ROAS = visits × `averageSpend` ÷ the sponsorship's value). The group edits the goals with `PUT /api/measurements/:eventId/goals` (`parseGoals`, `modals/GoalsModal.tsx`). The check-in page records through `/api/check-in/:code`: a scan answers a one-time `pass`, the coupon needs it once, and the visit needs it after the coupon plus the event's 4-digit `staffPin` (only the owner sees it, in the report; wrong PINs are limited per address). Brands measure their own campaigns the same way (`components/CampaignMeasurement.tsx` at the end of 성과 분석; visitors preview with `?role=브랜드`). The app picks the event to show with `defaultMeasurement` (`frontend/src/lib/measurements.ts`), and pages get its `metrics` and `report` as before. Accepting a proposal (a request or an offer) records one of the brand's sponsorships (`recordSponsorship` in `backend/src/lib/sponsorships.ts`), linked by `eventId` to a student event. `/api/analytics` shows those whose day has come, and one with an `eventId` takes its coupons, visits, estimated sales, value and ROAS goal from that event's measurement.
- Requests that can be guessed or flooded (login failures, email codes, admin token failures, check-in records) are counted per address with `createRateLimit` from `backend/src/lib/rateLimit.ts` and answer 429 past their limit. The counts live in memory; set `TRUST_PROXY` to the number of proxies (usually 1) behind a proxy so `req.ip` is the visitor; `true` lets callers forge their address and the server warns about it. Login, leaving and password change count the attempt with `take` before the slow password check. Tests clear them before each case with `clearRateLimits`.
- Sessions keep only `tokenHash` (sha256 of the browser's token, `hashToken` in `middleware/session.ts`). Sign-up needs `over14: true` besides `agreedToTerms`. `POST /api/auth/password` changes the password with the current one and ends the account's other sessions. `app.ts` sets the security headers, including a Content-Security-Policy that allows only this site's scripts (plus Google Tag Manager) and inline styles; a new outside script, font or API needs adding there.
- An event with an accepted proposal or a recorded sponsorship cannot be deleted (409, `isSponsored` in `lib/sponsorships.ts`); deleting one withdraws its waiting proposals on both sides, and accepting a proposal about a deleted event answers 409. When an account leaves, `freezeSponsorships` copies the live figures into its sponsors' records before its measurements go.
- `saveDatabase()` rejects only the caller whose write failed; later saves still run. Look up request input in plain lookup objects with `Object.hasOwn`, so names like `constructor` are not found.
