# 반응형 QA 보고서

2026-11-08, 브랜치 `responsive-system`을 빌드해 이 Mac에서 검증한 결과다. 기준은 `docs/RESPONSIVE_DESIGN_SYSTEM.md`, 고친 내용은 `docs/RESPONSIVE_AUDIT.md`.

## 도구

- **자동 점검**: `e2e/responsive.spec.ts`(Playwright, 설치된 Chrome). `npm run e2e`에 함께 돈다.
  - 실패로 막는 것: 가로 스크롤, 휴대폰의 16px 미만 입력창, 화면 밖으로 나간 팝업
  - 알리는 것: 잘린 글, 11px 미만 글, 44px 미만 터치 영역(`test-results/responsive-*.json`)
  - 크기를 골라 돌리기: `RESPONSIVE_SIZES=375x812,1280x800 npx playwright test e2e/responsive.spec.ts`
  - CI(`CI=true`)는 대표 크기 넷(320·390·768·1280)만 돈다. 열두 크기 전부: `RESPONSIVE_SIZES=all`
- **눈으로 본 것**: 휴대폰·태블릿·데스크톱 전체 화면 스크린샷(대시보드, 추천 매칭, 행사, 성과 분석, 회원가입 팝업)
- **실제 WebKit**: iOS 시뮬레이터(iPhone 18 Pro Max, iOS 27)의 Safari로 이 Mac의 빌드를 열어 확인

## 테스트한 크기와 화면

크기 12가지(320×700, 360×800, 375×812, 390×844, 393×852, 412×915, 430×932, 768×1024, 1024×768, 1280×800, 1440×900, 1920×1080)와, 390×844에서 브라우저 글꼴 125%.

화면:
- **방문자 22곳**: 소개, 대시보드, 추천 매칭, 상세 프로필, 단체 찾기(브랜드), 내 행사, 행사 상세, 성과, 리포트, 성과 분석(브랜드), 받은 제안(브랜드), 행사 일정(브랜드), 게시판, 둘러보기, 계약서 목록, 요금제, FAQ, 약관, QR 체크인, 직원 확인, 운영자 콘솔 로그인, 404
- **팝업 2개**: 로그인, 회원가입
- **회원 화면 6곳**(데모 학생단체로 로그인): 대시보드, 내 정보, 메시지, 계약서, 받은 협찬, 행사 등록

## 기능 회귀 테스트

| 기능 | 결과 | 근거 |
|---|---|---|
| 페이지 이동, 뒤로·앞으로 | 성공 | e2e flows(화면 이동·스와이프 테스트 포함) |
| 로그인·로그아웃, 2단계 로그인, 가입 | 성공 | "login popup logs into a demo account", "two-step login", "new group signs up" |
| 검색·필터 | 성공 | "brands and student groups can be searched and filtered", "search box's X" |
| 행사 등록·수정 | 성공 | "an event is edited from 내 행사", "event page on the form" |
| 협찬 제안·수락 | 성공 | "a student group proposes and the brand accepts", 제안 취소 |
| 데이터 저장(계약서, 배송, 후기, 지급 기록) | 성공 | 계약서·배송·후기·현금 지급 테스트 |
| 팝업 열기·닫기 | 성공 | 로그인·회원가입·결제 팝업 테스트, 이 점검의 팝업 테스트 |
| QR·쿠폰·방문 확인 | 성공 | "a participant takes the coupon and the store's staff confirm the visit" |
| 결제 테스트 환경 | 성공 | "pays the 15% fee to confirm"(테스트 결제, 실제 결제 아님) |
| 성과 리포트·CSV | 성공 | 리포트·분석 CSV, 상세 리포트 테스트 |
| 접근성(WCAG 2.1 A·AA 치명·심각), 영어 화면 | 성공 | `accessibility.spec.ts`, `language.spec.ts` 26개 |
| 타입 검사, 프런트 단위 테스트 312개 | 성공 | `npm run typecheck`, vitest |

e2e 합계: flows·accessibility·language 107개 + 반응형 37개, 모두 통과. 실제 결제와 외부 전송(메일, Kakao, Toss 실서버)은 테스트하지 않았다.

## 미검증 항목

| 항목 | 상태 |
|---|---|
| iOS Safari 실제 동작 | **일부 검증**. 시뮬레이터 Safari에서 추천 매칭 화면과 카드 버튼 배치, 검색창을 눌러도 화면이 확대되지 않음을 확인. 자동 점검은 Chrome(Blink)이고 Playwright WebKit은 설치하지 않았다 |
| 휴대폰 키보드가 입력창·버튼을 가리는지 | **미검증**. 시뮬레이터는 하드웨어 키보드가 붙어 화면 키보드가 뜨지 않는다. 실기기에서 회원가입·로그인·행사 등록 폼을 확인해야 한다 |
| Android Chrome 실기기 | 미검증(같은 Blink 엔진으로 자동 점검은 통과) |
| 화면 회전 | 자동 점검의 가로 크기(1024×768 등)로만 간접 확인. 실기기 회전은 미검증 |
| 노치·다이내믹 아일랜드·홈 인디케이터 | 시뮬레이터(iPhone 18 Pro Max)에서 상태 표시줄 밑 흐림과 하단 주소창 겹침이 없음을 확인. 하단 고정 요소가 없어 홈 인디케이터와 겹칠 것이 없다 |
| 운영자 콘솔 내부 화면 | 로그인 화면만 점검. 콘솔 화면은 기존 `accessibility.spec.ts`가 1280·390px에서 접근성만 확인한다 |
| 시각적 회귀(픽셀 비교) | 만들지 않았다. 글꼴 렌더링이 운영체제마다 달라 CI에서 흔들리므로, 대신 위의 수치 점검을 회귀 테스트로 둔다 |
