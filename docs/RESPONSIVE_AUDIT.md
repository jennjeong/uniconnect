# 반응형 점검 기록

2026-11-08에 전체 화면을 점검하고 고친 기록이다. 기준은 `docs/RESPONSIVE_DESIGN_SYSTEM.md`, 결과는 `docs/RESPONSIVE_QA_REPORT.md`.

## 구조

- 프런트엔드는 React + Vite, 스타일은 전역 CSS 한 파일(`frontend/src/index.css`, 약 23,000줄)이다. 컴포넌트는 그 클래스 이름을 쓴다. Tailwind는 있지만 화면에는 쓰지 않는다.
- 이번 작업은 프레임워크를 바꾸지 않고, 그 파일의 토큰과 끝의 "반응형 디자인 시스템" 구역으로 정리했다.
- viewport 메타(`width=device-width, initial-scale=1.0`)는 있었고, 확대를 막지 않는다.

## 찾은 문제와 고친 방법

## 고친 파일

- `frontend/src/index.css`: 토큰(`--text-*`, `--space-*`, `--touch-target`, `--control-h*`, `--content-max`, `--form-max`), `font-size` px→rem, 파일 끝 "반응형 디자인 시스템" 구역
- `frontend/src/pages/MatchesPage.tsx`, `GroupsPage.tsx`: 카드 버튼 이름
- `e2e/responsive.spec.ts`: 자동 점검(새 파일)
- `docs/RESPONSIVE_DESIGN_SYSTEM.md`, `RESPONSIVE_AUDIT.md`, `RESPONSIVE_QA_REPORT.md`

## 확인했지만 고치지 않은 것

- **하단 내비게이션**: 이 앱에는 없다(메뉴는 머리글의 Menu와 전체 화면 메뉴). 휴대폰 Safari의 하단 주소창과 겹치는 고정 요소도 없다.
- **긴 이메일·주소**: `overflow-wrap: break-word`가 이미 전체에 있고, 점검에서 잘린 글이 0건이었다.
- **팝업**: 휴대폰에서 아래에서 올라오는 시트이고, 12가지 크기에서 화면 밖으로 나간 것이 0건이었다.

## 남은 것

- **CSS 정리**: 미디어 쿼리 58곳, `!important` 10곳이 파일 곳곳에 있다. 이번에는 겹치는 값을 토큰과 끝 구역으로 모았고, 23,000줄 전체를 토큰으로 바꾸지는 않았다. 컴포넌트를 고칠 때마다 그 부분의 숫자를 토큰으로 바꾼다.
- **달력 날짜 칸**: 320px에서 폭 32~38px(높이는 40px 이상). 일곱 칸이 들어가야 해서 그대로 둔다.
- **제안 취소 링크**: 누를 자리는 넓혔지만 점검 도구는 `::after`를 재지 않아 작게 나온다.
- **간격 토큰**: 기존 컴포넌트의 padding·gap 숫자를 모두 `--space-*`로 바꾸지는 않았다(값은 대부분 이미 4의 배수).
- **실기기**: 실제 iPhone·Android의 키보드와 입력창 겹침, 회전은 `RESPONSIVE_QA_REPORT.md`의 미검증 항목에 적었다.
